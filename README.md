# Director's Brief

디렉터처럼 지시하면 AI가 디자이너처럼 일합니다.
목적 6가지와 디자인 유형 22가지로 나눈 실무형 디자인 프롬프트 100개입니다.

**사이트:** https://uxidesigner-ux.github.io/directors-brief/

## 쓰는 법

첫 화면은 목차(인덱스)예요. 바인더 칸막이 두 장으로 나뉘어 있어요.

| 칸막이 | 들어 있는 것 | 이런 사람에게 | 누르면 |
|---|---|---|---|
| 프롬프트 100 | 하려는 일 6가지 + 전체 | 만들 게 정해진 사람 | 그 일만 걸러진 목록 화면 |
| 코스 5 | 순서가 정해진 프롬프트 묶음 | 처음 쓰는 사람 | 코스 시트 (단계별 복사) |

"하려는 일"과 "전체 100개"는 같은 목록으로 들어가는 다른 입구이고, 코스는 그 목록의 프롬프트를 순서대로 묶은 것이에요. 이름이나 번호를 알면 맨 위 검색창에서 바로 찾으면 돼요.

1. **고르기**: 타일 6개(브랜드 만들기, 판매·마케팅, 앱·웹 화면, 콘텐츠·SNS, 발표·보고, 점검·개선) 중 하나를 누르면 목록 화면이 열려요. 목록 화면에서는 위쪽 줄로 하려는 일을 바꾸고, 필터로 유형·결과물을 거릅니다. "처음"이나 뒤로가기로 첫 화면에 돌아와요.
2. **처음이라면 코스로**: 브랜드 처음 만들기, 랜딩페이지 출시, 앱 MVP 화면 설계, 투자 피치 준비, 매주 SNS 운영. 같은 대화에 순서대로 붙여넣으면 앞 결과가 다음 단계의 재료가 됩니다.
3. **내 브리프 채우기**: 서비스 정보 8가지를 한 번에 한 질문씩 적으면 100개 프롬프트의 빈칸이 채워집니다. 비워 둔 칸은 `[ ]`로 복사됩니다. 브라우저(localStorage)에만 저장됩니다.
4. **복사해서 붙여넣기**: 카드의 복사 아이콘이나 상세 화면의 "프롬프트 복사"를 누르고 AI에 붙여넣습니다. 책갈피를 누르면 보관함에 모입니다.

주소 끝에 `#list`(전체), `#list-brand`(하려는 일별), `#042`(프롬프트), `#c-launch-page`(코스)를 붙이면 그 화면이 바로 열립니다.

## 검증 (브랜드 전략 5개)

"브랜드 전략" 유형 5개(001, 005, 006, 014, 017)를 실제 AI에 돌려 블라인드로 채점했습니다.

- **비교 대상 3가지:** ① 이 프롬프트 ② 같은 정보를 준 평범한 한 줄 요청 ③ 플러스엑스의 캐시노트 BX 리뉴얼 공개 케이스
- **테스트 사례:** 캐시노트의 공개된 사실을 그대로 쓰고 이름만 가상의 "온장부"로 바꿨습니다.
- **채점 기준:** 6개 구분(전략, 버벌, UX, UI, GUI, 비즈니스)에 지표 16개, 1~5점입니다. 어느 쪽이 이 프롬프트인지 모르는 별도 평가자가 채점했습니다.

| | 전체 평균 | 과제 검수 통과 |
|---|---|---|
| 플러스엑스 공개 케이스 | 2.25 | – |
| 평범한 요청 | 3.44 | 7/15 |
| 수정 전 프롬프트 | 3.88 | 13/15 |
| 수정 후 프롬프트 | 4.38 | 15/15 |

수정 후 프롬프트는 16개 지표 모두에서 공개 케이스와 같거나 높았습니다. 한계도 분명합니다.

- 공개 케이스는 선별된 쇼케이스이고, 실제 납품 문서는 더 풍부할 수 있습니다.
- 실제 조형 완성도(로고, 색의 아름다움)는 평가하지 않았습니다.
- 답변도 채점도 Claude가 했고, 사례는 하나입니다.

수정한 내용:

- 브리프에 선택 칸 "브랜드 코어"를 추가했습니다. 001 결과 맨 끝의 4줄(핵심 개념, 태그라인, 모티프, 확정 기준)을 붙여 넣으면 브랜드 프롬프트들이 같은 결정을 이어받습니다.
- 수익 모델을 전략 프롬프트에 넣었습니다.
- 주어진 사실을 바꾸는 가정을 막았습니다.
- 검수 결과표 출력을 없앴습니다.
- 하나의 핵심 개념에서 모든 결정을 출발시키는 원칙을 추가했습니다.

## 검증 (GUI: 모티프·컬러·타이포 3개)

010 모티프, 011 컬러, 012 타이포는 결과가 코드로 나와서 실제 화면으로 렌더링해 비교했습니다.

- **비교 방식:** 같은 홈 화면 틀에 각 답변의 색·글꼴·크기 값을 그대로 넣었습니다. 모티프는 답변 코드를 그대로 띄웠습니다.
- **채점 방식:** 별도 평가자가 블라인드로 지표 7개를 채점했습니다(역할 구분, 대비, 서비스 성격, 타입 위계, 모티프, 시각 완성도, 구현 완성도).

| | 평범한 요청 | 수정 전 | 수정 후 |
|---|---|---|---|
| 1차 채점 | 3.86 | 3.57 | – |
| 2차 채점 | 2.86 | – | 4.14 |

1차에서는 졌습니다. 001의 브랜드 코어가 글자 크기까지 못 박아 금액 위계가 약했고, 주의 칩 배경이 빠졌으며, 모티프 코드가 깨졌습니다.

수정한 내용:

- 브랜드 코어에는 화면 수치를 넣지 않게 했습니다.
- 컬러는 상태마다 글자·면·테두리를 한 세트로 정하게 했습니다.
- 타이포는 핵심 숫자를 바로 아래 단계보다 1.4배 이상 크게 하게 했습니다.
- 모티프는 UI 부품과 마케팅 양쪽에 적용하게 했습니다.
- 코드 결과물은 "그대로 붙여도 가려짐·잘림·줄바꿈 깨짐이 없는가"를 검수하게 했습니다.

한계도 분명합니다.

- 평범한 요청은 두 채점 사이에 점수가 크게 달라졌습니다. 평가자 기준 차이와 렌더 값 매핑을 더 정확히 한 영향입니다.
- 같은 차수 안의 비교만 의미가 있습니다.
- 플러스엑스의 실제 조형 완성도는 이미지 없이 비교할 수 없어 평가하지 않았습니다.

## 검증 (판매·마케팅: 히어로 020, 가격 021, 비교표 033)

같은 방식(렌더링 + 자동 측정 + 블라인드 채점, 지표 8개)으로 검증했습니다.

| | 평범한 요청 | 우리 프롬프트 |
|---|---|---|
| 1차 | 3.62 | 3.79 |
| 2차 (수정 후) | 3.79 | 3.54 |
| 3차 (간결 버전) | 3.38 | 3.92 |

- **우리 쪽이 꾸준히 이긴 지표:** 신뢰·정직(불리한 항목 표기, 과장 없음)과 접근성 측정값(대비 미달 0, 버튼 48px 이상, 동작 줄이기)입니다.
- **2차 수정의 효과:** 측정 이벤트와 수익 진입점을 요구하자 비즈니스 지표가 2.67에서 4.0으로 올랐습니다. 하지만 코드가 길어지면서 버그가 늘어 시각·UI 점수는 떨어졌습니다. 숨김 토스트 노출, 40px 칩 같은 문제입니다.
- **3차 조치:** 020·021·033의 단계와 산출물을 절반 가까이 줄이고, 완성도 검수는 한 줄로 압축했습니다. 3차에서 전환 설계(4.33 대 2.67), 신뢰(4.67 대 3.67), 비즈니스(3.67 대 2.33)를 이겼습니다. 시각 완성도는 여전히 3.0 대 3.67로 졌습니다.

## 간결화 (코드형 프롬프트 38개)

판매·마케팅 검증에서 지시를 줄인 간결 버전이 가장 좋은 결과를 냈습니다(3.92 대 3.38). 그래서 같은 원칙을 결과가 코드로 나오는 프롬프트 전체에 적용했습니다.

- **원칙:** 단계는 결정을 가르는 것 2개, 산출물은 코드를 포함해 3개 이내, 검수 기준 3개는 그대로입니다.
- **제외:** 010 모티프, 011 컬러, 012 타이포는 긴 버전으로 검증에서 이겼기 때문에 그대로 두었습니다.
- **검증 상태:** 020, 021, 033 외 35개는 개별 재검증 전입니다.

## 사용감

- 모바일 우선: 가로로 넘기는 줄은 목록 화면의 "하려는 일" 레일 하나뿐이고, 디자인 유형·결과물은 필터 시트에서 고릅니다.
- 첫 화면에서 목록으로 갈 때는 화면이 밀려 들어오고, 누른 타일 이름이 목록 제목 자리로 이어집니다(View Transitions 지원 브라우저). 뒤로 가면 반대로 움직이고 첫 화면의 스크롤 위치가 돌아옵니다.
- 시트는 뒤로가기나 아래로 끌어서 닫힙니다. 홈 화면에 추가하면 앱처럼 열립니다.
- 시스템 설정에 따라 다크 모드로 바뀌고, "동작 줄이기" 설정에서는 애니메이션을 끕니다.
- 조사(은/는, 이/가, 을/를)는 입력한 브랜드명 받침에 맞춰 자동으로 바뀝니다.
- 데스크톱에서 `/` 키를 누르면 검색이 열립니다. 선택 버튼 묶음은 좌우 방향키로 옮겨 다닙니다.
- 검색은 제목에 맞는 것을 먼저 보여주고, 제목 밖에서 맞았으면 어디서 맞았는지 한 줄로 보여줍니다. `피치`, `ppt`, `홈페이지`, `인스타` 같은 말과 `ㄹㄱ`(로고) 같은 초성도 찾습니다.
- 상세 화면의 입력칸마다 예시가 있습니다. "예시 넣기"를 누르면 채워지고, 내 상황에 맞게 고쳐 쓰면 됩니다.
- 링크를 메신저에 붙이면 공유 이미지가 함께 보입니다.

## 프롬프트 구조

복사되는 프롬프트는 `app.js`의 `compose()`가 아래 순서로 조립합니다.

1. **역할**: 해당 분야 실무자로서의 구체적인 경력
2. **프로젝트 맥락**: 내 브리프에서 그 프롬프트에 필요한 항목만
3. **과제**: 무엇을, 어떤 기준으로
4. **진행 방식**: 단계별 작업 순서. 방향 탐색이 필요한 프롬프트는 "3안 먼저 보기 / 바로 완성하기"를 고를 수 있습니다
5. **산출물**: 받을 결과물의 형식
6. **디렉팅 원칙**: 아래 10가지 중 그 프롬프트에 맞는 것만 (상세 화면에서 끌 수 있음)
7. **자기 검수**: 출력 전에 AI가 스스로 점검할 기준. 제품·전환·검수 프롬프트에는 5대 기준 자체 채점이 붙습니다
8. **공통 지시**: 부족한 정보는 `[가정]`으로 표시하고 구조화해서 답하기

### 디렉팅 원칙 10

1. 쓰임새 먼저
2. 3초 규칙
3. 해석은 시스템이, 선택은 사용자가
4. 수익과 연결
5. 완성도는 수치로 (8px 그리드, 1.25 타입 스케일, 대비 4.5:1, 한글 본문 14px 이상)
6. 상태까지 디자인 (로딩·빈 화면·오류·성공)
7. 조작하고 싶은 인터랙션 (0.1초 반응, 되돌리기, 의미 있는 움직임만)
8. 말은 지시문처럼
9. 냉정한 근거
10. 누구나 이해하는 말

## 프롬프트 추가·수정

`data/p*.js`에 아래 형식으로 넣으면 됩니다.

```js
{
  id: '101', p: 'product', t: 'app', out: 'code', x: true,  // x: 3안/바로 완성 선택 지원
  title: '카드에 보일 제목',
  role: 'AI에게 맡길 역할',
  ctx: ['brand', 'audience'],                    // 내 브리프에서 쓸 항목
  in: [{ k: 'screen', l: '대상 화면' }],          // 이 프롬프트에서만 받는 정보
  task: '{brand}의 {screen} 화면을 ...',          // {키}는 입력값으로 바뀜
  steps: ['...'], output: ['...'], checks: ['...'],
  next: ['다음 단계 프롬프트']
}
```
